01 Ask it right

1Talk it through

Paste the Discovery Interview, then talk the way you'd brief a colleague. It asks; you answer.

Principle

Let the AI ask the questions. "I don't know" is an answer: it becomes an open item, not a guess.

2Sort the specifics

Every tool, number or story you mention is Binding, Example, Background or Guess. Confirm the sort.

Principle

Everything you say pulls on the answer. Say which details are rules.

3Confirm the brief

One fact per item, with units and a source. No design yet. Gaps are open items, never TBD.

Principle

A standard, never a summary. Confirming is your signature.

02 Check it

4Lint, then review

New chat. The lint runs code on the brief. Then the review checks every item against your own messages, numbered M1, M2..., on fixed scales. Patch only what the gate marks Patch, back in the brief's own chat.

Principle

Let code count. Review in a new chat, against what you actually said.

03 Choose and build

5Choose from the menu

The AI lays out distinct designs with units used, what each can estimate and what it is aliased with. You pick. The decision record goes to a new chat.

Principle

The AI lays out the options; you make the choices that cost something.

6Build the run sheet

Run sheet and analysis plan: model terms, pass rules, groups judged separately, and the rule for excluding a run. Then the lint checks limits, budget, design shape, randomization and aliasing by code.

Principle

Decide how you'll judge the result before you see it.

04 Own it

7Walk it

Walk the run sheet as if you were loading the wafers. A missing or wrong requirement goes into the brief as a new version, with a change log line, and the run sheet is rebuilt in a new chat. A run sheet that missed the brief is fixed in its own chat.

Principle

Accuracy comes from cycles. Review what was built, fix the requirement, rebuild.

8Risk and release

Give the risk step the process flow, so it can ask what every later step assumes. The release review lists every open item that could change a result, with an owner.

Principle

You own what you hand on. Name what's still open, and who owns it.

10Make it better every time

  1. Catch it: what did you fix by hand?
  2. Fix the prompt, not just the answer. Keep it general.
  3. Test it: the Prompt Grader, then rerun on the same input.
  4. Log it: version, what changed, why.

The test for any saved prompt: would it still work on another tool, another film, another fab?

11With real data

  1. Recipes are our know-how. Share only what the question needs.
  2. A person decides every recipe change.
  3. Your stats package and change system stay the record.

12The other playbooks

  • Analyze experimental data: counts and groups, checked by code
  • Research: open every source you'd quote, with its conditions
  • Qualify a change: what else does it touch?
  • Write it up: label every number measured or predicted
