AI for Troubleshooting · Cheat sheet

The 8D, run as a loop.

Frame it, update it, plan a check, run it, repeat until the qual passes. Then prevent and close. Every prompt is in playbook.md in your case kit. Works in Gemini Enterprise or Copilot Chat.

The loop
1

Frame the event

D0 to D3

Let it interview you. Describe it in your own words; it asks up to three questions a round and marks each part Clear, Fuzzy or Unknown.

Every specific gets sorted: binding (has a source), example, background, or guess. A guess becomes a cause to test, never evidence.

Check

  • No cause in the problem statement
  • Containment covers everything that ran since the change, not just the tool
  • Causes listed from how the subsystem works, wider than anyone's hunch
  • Review in a new chat, with only your own answers
2

Update the causes

D4

Every cycle: new chat, the latest 8D record, only the new evidence. The record is the memory; old chats stay closed.

Check

  • Counts come from code that ran. Otherwise: COUNT NOT VERIFIED, and nothing changes.
  • Claims quote the line, with document and section
  • Ruled out only when evidence contradicts it
  • Confirmed only by a result that would differ if you were wrong
  • The simplest check that splits the most causes comes next
3

Plan a check

D4 to D6

Decision menu first: which causes this cycle splits, downtime, parts, when to stop and call. You pick; the plan follows.

ConditionsOn every reading: temperature, soak, setpoint
ConfirmationNo repair until a cause is confirmed
BranchesEvery result goes to a step, a call, or the qual
SafetyCited from the procedure, never made up

Lint with code (units, branches, IDs), then review in a new chat. Then the engineer signs the release certificate.

4

Run it and report

The tech's notes, as written, become a results report tied to each step.

  • Observation apart from interpretation
  • Every reading with units and conditions
  • Off-plan work flagged
  • The tech confirms it before it goes back into the update
5

Finish

D5 to D8
DAsk AI forYou check
D5 FixThe fix for the confirmed causeConfirmed first, or required by the procedure anyway
D6 VerifyThe qual with its pass criteria, agreed before the workThe tool returns to production here
D7 PreventActions for the root cause and the escape point, and "where else could this happen?"Every action answers one of the two, has a way to verify it, and a named owner
D8 CloseA closure summary and a lesson learnedSymptom in the words people search; the earliest sign; every line traced to the record
Check it
6

Red flags

Slow downAsk instead
A cause in the problem statement"Rewrite it with no cause."
A count that doesn't match the file"Run code for the count. Which rows did you leave out?"
A part swap before any check"What cheaper check splits the same causes?"
A reading with no temperature or units"What conditions, and what gets recorded?"
A torque, limit or bulletin you can't find"Quote the line." No line, no step.
"Confirmed" after one consistent result"What else would read the same?"
A D7 action with no owner"Who owns it, and how do we know it worked?"
7

Three lessons

H
You step in: supply the facts, pick each cycle, decide what's a repair.
R
You check it: code for counts, quotes for claims, a new chat for reviews.
O
You sign it: containment, plan, actions, lesson.

Process troubleshooting

Same loop and prompts. Lots, wafers and sites instead of chamber runs; a lot hold; metrology or a split lot as the check; release criteria as the qual.

8

With real data

  1. Describe the situation. Leave out names you don't need.
  2. A person decides every hold, fix and recipe change.
  3. Confirm on the tool what the data only suggests.
9

Make the playbook better

  1. After each event, write one line on what you had to correct.
  2. Change the prompt that caused it.
  3. Rerun it on the same input before you save it.
  4. Log the change at the bottom of the playbook.
